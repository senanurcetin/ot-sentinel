**An explainable anomaly dashboard for industrial (OT) telemetry:** a statistical detector decides whether a reading is anomalous and which sensors drive it, and an LLM only explains that verdict, with a rule-based fallback when the LLM is unavailable.

## Key results

Seven detectors evaluated on the public [BATADAL](https://www.batadal.net/data.html) water-distribution attack benchmark (43 signals, hourly, 14 attacks in two files), all held to the **same false-alarm budget**. Detectors learn from a year of attack-free data; the headline is a later, unseen test file. Protocol v3 was [fixed before its first run](docs/protocol-v3.md).

How to read it:

- **"Attacks caught" says little.** False alarms alone would land in almost every attack (attacks last 24-110 hours); use precision, attack hours caught and PR-AUC against the random-guess value.
- **Adding time did not help.** No temporal detector beats the z-score on the test file and two are worse; the EWMA does better only on the 2016 file.
- **The explanations mostly point at the right equipment.** During an attack the z-score's three strongest signals include an attacked one roughly three times as often as chance, except for attacks that replay normal readings ([details](docs/case-study.md#does-the-explanation-point-at-the-attacked-equipment)).

Per-attack tables, data drift and the protocol amendment: [case study](docs/case-study.md) · [model card](MODEL_CARD.md).

## Quick start

```bash
npm install
cp .env.example .env     # optional: add GEMINI_API_KEY; without it the rule-based fallback is used
npm run dev              # http://localhost:9002 , toggle "Simulate Attack"
```

Docker:

```bash
docker build -t ot-sentinel .
docker run --rm -p 9002:9002 -e GEMINI_API_KEY=your-key -v ot-sentinel-data:/data ot-sentinel  # volume keeps verdicts
```

Quality checks:

```bash
npm run lint
npm run typecheck        # includes test files
npm run test:coverage    # Jest + coverage thresholds
npm run build
npm run test:e2e         # Playwright; run `npx playwright install chromium` once
E2E_BASE_URL=https://your-deployment npm run test:e2e   # same suite against a deployed instance
cd analysis && pip install -r requirements-dev.txt && ruff check . && pytest
```

## Details

### What it does

- Streams simulated temperature, pressure, vibration and traffic readings once a second and scores each sample against an attack-free baseline, showing per-sensor z-scores and each sensor's share of the risk score.
- On a CRITICAL sample, opens an alert with a summary and suggested actions, written by Gemini when available and by the rule-based fallback otherwise; the dialog says which.
- Lets a user mark an alert as a confirmed threat or false alarm (`POST /api/feedback`). The forensic report shows the share marked false alarm per sensor (`GET /api/feedback/summary`, aggregates only). Stored in SQLite when `FEEDBACK_DB_PATH` is set (default in the Docker image), in memory otherwise ([contract](docs/operator-feedback-analytics.md)).
- Simulates an attack on demand and exports a forensic report as CSV (spreadsheet-formula safe).
- [`/offline-replay`](https://github.com/senanurcetin/ot-sentinel/blob/main/docs/LOCAL_REPLAY_WORKBENCH.md): a browser-only workbench for checksummed three-sensor JSON recordings ([contract](docs/OFFLINE_REPLAY_CONTRACT.md)). It never uploads a file and can export a JSON report of reviewed windows with checksum provenance.

### BATADAL research pages

- [`/batadal-history`](docs/BATADAL_VERIFIED_HOURLY.md): **660 hourly rows** from the official 2016 dataset04 around seven attacks, with 12 hours of context on each side and all 43 signals. The source CSV's SHA-256 matches the pinned analysis digest; regenerate with `analysis/export_verified_hourly.py` and your own copy of `BATADAL_dataset04.csv` (no raw CSV is stored).
- [`/batadal-test-history`](docs/BATADAL_VERIFIED_TEST_HOURLY.md): **575 hourly readings** from the SHA-256-verified 2017 test ZIP around attacks 8–14, all 43 channels, no interpolation. Attack intervals come from the published annotations because the ZIP is unlabelled. Re-check with `python3 analysis/export_official_test_hourly.py --check`.
- Both pages have a retrospective detector selector: a dashed marker shows the first alarm time reported by the offline evaluation, alongside false alarms/day and expected hits from chance. The supervised reference is unavailable on the 2016 training period.
- [`/batadal-explorer`](docs/BATADAL_EVIDENCE_EXPLORER.md) (linked from `/case-study`): compare detectors on the 2017 test or 2016 file, read attack descriptions and outcomes, and browse the 43-signal feature inventory and top drift features from the committed offline results.

Data: BATADAL / Taormina et al. (2018), [CC BY 4.0](https://github.com/scy-phy/www.batadal.net/blob/master/LICENSE.md); adaptations are documented on each page.

### Architecture

Next.js App Router (React 19, TypeScript), Genkit + Gemini 2.5 Flash, Tailwind + shadcn/ui, Recharts, zod. [`analysis/`](analysis/README.md) holds the Python evaluation pipeline and generates the detector constants in `src/data/model/scorer-params.json` (`analysis/export_model.py`); the model card parameter table comes from the same file and `pytest` fails if either goes stale. Diagrams and the alert sequence: [`docs/architecture.md`](docs/architecture.md). More docs: [documentation guide](docs/README.md).

### Security and demo access

Security headers and CSP, per-client rate limits, validated inputs, a model timeout with fallback, and CSV formula-injection protection. Scope, residual risks and an ATT&CK for ICS mapping: [threat model](docs/threat-model.md). Report issues via [`SECURITY.md`](SECURITY.md).

Set `DEMO_BASIC_AUTH=username:random-secret-of-at-least-16-chars` at runtime to put application pages, API routes and the AI server action behind a shared HTTP Basic challenge. Leave it absent for the open demo; an empty or malformed value fails closed (503). `/api/health` and static assets stay public. Failed guesses are capped per server instance without trusting forwarded-IP headers. See [demo access and deployment security](docs/demo-access.md).

### CI and deployment checks

Automatic PR jobs run in CircleCI (`web-quality`, `analysis-quality`, `browser-e2e`); GitHub runs Docker, CodeQL, `npm audit`, `pip-audit` and secret scanning (plus weekly scans), and keeps its web/Python/browser workflows as manual fallbacks ([CI coverage contract](docs/ci-coverage-contract.md)).

A read-only smoke check verifies a deployed preview at an exact commit:

```bash
DEPLOYMENT_SMOKE_URL=https://your-exact-preview.vercel.app \\
DEPLOYMENT_SMOKE_EXPECTED_SHA=<full-40-character-git-commit-sha> \\
npm run smoke:deployment
```

It requires the full 40-character SHA before any request, never follows redirects, rejects SSO login HTML even on HTTP 200, and checks `/`, `/offline-replay`, `/batadal-explorer`, `/batadal-history`, `/batadal-test-history`, `/case-study` and `/api/health` on one origin. A missing or mismatched commit, a login challenge or an unavailable route fails. Optional `DEPLOYMENT_SMOKE_COOKIE` or `DEPLOYMENT_SMOKE_BYPASS` values are never printed. `npm run test:deployment-smoke` tests the checker offline in CI. Protected-preview and release acceptance is tracked in [issue #72](https://github.com/senanurcetin/ot-sentinel/issues/72).

## Limitations

- **Demo only.** Live telemetry is synthetic with three sensors; there are no real protocol adapters, and it must not be connected to a PLC, DCS or live control system. The LLM never makes detection or control decisions.
- **Modest detection.** The best detector flags a minority of attack hours and is right about half the time it alarms; no detector is near a deployable operating point. The CUSUM alarms in most attack-free hours.
- **Small sample.** Seven attacks per file make detector differences anecdotal; intervals are wide and overlap, and even the z-score's lead over static limits on the test file is not established.
- **Drift.** The attack-free reference is from 2014, the evaluation files from 2016-2017, and one pressure signal drifted ([data drift](docs/case-study.md#data-drift)); part of every false-alarm figure is that shift.
- **The dashboard scorer is not what was measured.** BATADAL evaluates the method on 43 signals offline; the live scorer is a 3-signal, per-sample static baseline with no missing-data or stuck-value detection. The supervised gradient-boosting row is an optimistic reference, not a deployable detector.
- **The history pages are excerpts.** Attack windows only: no full-horizon replay, no new model inference, no hourly risk curve, and source timestamps have no declared timezone (not UTC).
- **Operator verdicts are self-reported labels**, not verified ground truth or a detector metric, and are not yet used to tune anything.
- **Demo access is not access control.** The shared password has no user-level authorization, SSO, audit identity or distributed throttling, and its global failure counter lets an attacker lock out all users. Use provider SSO/VPN and an ingress WAF for public access.
- **Not released to production.** Green CI or a `READY` preview is not release acceptance; authenticated browser/accessibility checks, origin authorization, API write protection and rollback rehearsal remain open ([#72](https://github.com/senanurcetin/ot-sentinel/issues/72)).
